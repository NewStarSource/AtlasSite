## 重复演练

先从当前两端源码构建二进制，然后在星图仓库根目录运行：

```powershell
python scripts/test_wiki_examples.py --account-bin ..\StarAccount\.local\november\staraccount.exe --atlas-bin .local\november\staratlas.exe --report .local\november\wiki-examples.md
```

运行器只创建临时数据库、随机本机端口和三个合成身份，不接受已有实例地址或数据库；只在临时配置开启 Wiki，结束时清理自己的进程与目录。报告保留步骤、耗时、来源及构建摘要，不保存凭据。运行时不重新访问外部来源，资料变化需另行核对。

每例完成发现页编辑冲突、正式条目私有提交与审核发布、退回原稿重提、旧建议冲突、新建议采纳及错误输入保留。发现页和正式条目分别创建，没有模拟尚未实现的升级关系。审核按钮由脚本的团队身份提交，不能视为独立人工复核、真人多人协作或图形验收。

## 真人试用待验收步骤

在获准开启 Wiki 的独立内部实例进行，不直接开启生产开关：

1. 实际参与者阅读来源，分别担任记录者、共同编辑者和有效团队审核人员。
2. 从“更多 → Wiki”填写发现页，两人保留不同版本的表单，实际触发冲突并确认输入仍在。
3. 从“提交条目”填写相应模板，核对脚注。审核人员退回一稿，提交者从提交记录打开原稿，修改后重提。
4. 提出字段或段落建议，实际完成一次采纳和一次具体理由退回，检查版本、署名、来源与结果。
5. 检查桌面、窄屏、键盘和关闭 JavaScript 的基本操作，记录溢出、焦点及输入保留问题。

记录日期、参与者化名与角色、实例版本、样例、实际步骤、问题及修复后结果，不把脚本身份填写为真人参与者。

## 演练发现的问题

| 问题 | 原行为 | 修复后 |
| --- | --- | --- |
| 退回稿重提 | 已发布条目的重提入口载入公开稿，丢失退回稿输入 | 打开本人指定原稿，保留正文、字段、来源与原基线；旧基线仍不能覆盖新内容 |
| 建议填写错误 | 只返回错误结果，没有编辑表单 | 保留位置、原段落、建议、依据、来源及原基线，返回经过转义的可修改表单 |

其他人和团队不能代开本人的私稿重提入口，撤回和受限内容不能通过该地址读取。修复不自动重绑版本或绕过冲突校验。

# 星图测试上线与首版范围规范 v1.3


## 1. 范围与最低权利能力

| 批次 | 功能 | 明确关闭的能力 |
|---|---|---|
| 核心首发 | 新星登录/化名、社群分类/主题浏览、动态/回复、图片、基础搜索、已公开公告/新人指引与讨论合集只读、屏蔽和隐私控制、举报及申诉、必要通知、本人导出/注销/恢复 | 活动、社群工具编辑、Wiki 编辑、正式投票、复杂推荐、公共 API、Webhook |
| 第二批 | 社群代表的公告/指引和合集维护、线上活动及日历、作品展柜、无约束力意见收集、发现页/Wiki 正式条目与脚注/版本/建议、基础关系、成员及代表选举、讨论型/决策型议题与多方案表决、联署/实施台账、独立候补复核选举及分案、基础推荐、只读 API | Wiki 自动发布、Webhook、复杂合并拆分/消歧 |
| 后续 | 经独立验收的 Wiki 自动发布、Webhook、复杂合并拆分/消歧与推荐实验 | 每项独立开关，不随其他功能默认开启 |

导出、注销、屏蔽、举报和申诉为接入真实用户前的最低能力，不因缩小首版而延期。先团队录入获授权示例，再邀请用户，第二批才开放用户提名/社群创建和代表选举。未开放投票期间仅限公告的邀请测试，临时团队最多运行 90 天，只维护与执行既定安全规则；期满须开放并完成授权选举，未完成则保持测试/只读，不进入全量公开。该过渡范围、期限和人员向邀请用户明示。

邀请阶段可用受限表单收集议题并记录决定执行，但不虚构已选出的候补复核组。常态全站治理开放前先完成执行团队及独立候补池的启动选举；启动选举属于法定选举，不要求先完成普通成员联署或已有候补池批准，适用现有秘密选票、法定人数和安全限制。启动选举发生涉团队争议时按 SA2 待补员过渡规则处理，不由被投诉者最终裁决。独立候补池未组成、授权回避测试未通过不得进入小范围公开。

## 2. 测试范围

每次发布跑受影响的 Go 单元/HTTP/迁移/权限测试及核心回归；已开启功能覆盖 Markdown、上传、隐藏链、通知/任务幂等、导出/注销。分类浏览验证层级、旧路径和待分类；引入第二批后加入社群工具引用撤回、意见收集隐私、议题类型/升级、多方案补投、投票快照与秘密选票、Wiki 并发版本、成员权限和 OpenAPI 契约。浏览器覆盖启用功能，在 360px/1280px、键盘和无 JavaScript 路径检查。

安全回归包含隐藏后旧 URL/图片/搜索/ETag 不泄漏、多个限制独立解除、删除备份恢复不复活、投票结束并发改票、双人复核权限、失去租约重试、共同作者异议不误发布。关闭功能的路由、后台任务和页面入口均拒绝操作，不只隐藏菜单。

合集、展柜、日历及公告的列表、通知和导出都要复查原对象授权；作者撤回、删除、移出社群及代表/整理者授权到期后，旧 URL、缓存与异步任务不能继续展示内容或取得编辑权。意见收集的个人选项仅本人可见，汇总不能生成正式决定；议题全站广播不得绕过关闭通知，具体提及不得绕过拉黑关系。

## 3. 性能与可靠性指标

在独立环境使用合成 1 万账户及代表性内容/图片，100 并发、读写 90:10，预热 10 分钟、持续 30 分钟并叠加后台任务；记录数据规模、硬件、命令、配置和原始分位数。1000 日活和数千次日读写是容量假设，不将其等同于固定 QPS。

| 指标 | 门槛/窗口 |
|---|---|
| 核心读/普通写 | p95 <500ms / <1s，非预期 5xx 与超时 <1%；鉴权错误单独统计 |
| OAuth | 有效、用户未取消的登录尝试成功率 >=99%，邀请阶段连续 7 天且至少 100 次；外部故障单独计数不能从总数抹除 |
| 写锁/容量 | 告警与升级按 TECH-01；无无限等待或 WAL 持续增长 |
| 权限/隐私 | 受影响越权与可见性回归 100% 通过，零已知高风险泄露 |
| 搜索/推荐 | 查询分组与权重生效符合 TECH-14；已隐藏内容新读取立即过滤，物理清理最大 5 分钟 |
| 任务 | 普通队列 p95 等待 <15 分钟、最大 60 分钟，安全告警即时；人工案件另按 TECH-15 |
| 备份/恢复 | 近 30 天定时备份成功 >=99%，且最新有效快照不超过 60 分钟；上线初期使用全部可用窗口并标注天数。实测数据库 RPO <=1 小时、一般故障 RTO <=4 小时 |
| 数据删除 | 每日到期清理 100% 执行，过期未清理立即告警；恢复演练覆盖删除清单和敏感密钥 |
| AI | 仅按 TECH-15 影子/灰度样本和门槛开放，不把未检验功能标成通过 |
| Webhook | SSRF 重绑定、HMAC、重放、失序、重复、最大 6 次尝试和自动暂停测试全部通过后才开放 |

## 4. 安全审查与恢复

首次接入真实用户前完成单独的 AI 安全代码审核任务及实际安全测试，覆盖 OAuth、对象权限、上传、CSRF、XSS、SQL 注入、敏感出站；后续 API/Webhook 开放前增加限流和 SSRF。AI 审核须记录发现、修复与复查证据，不称为独立第三方安全认证，不要求外部人员或多人签字。每月隔离恢复 DB 和必要附件，验证权限、删除清单、审计锚点、撤销凭据和备份生命周期，由 AI 汇总实际值及剩余风险，项目负责人按操作清单核验恢复结果。严重问题未解决不放量。

## 5. 发布闸门

| 阶段 | 最短观察/通过条件 | 退出条件 |
|---|---|---|
| 内部测试 | 7 天；核心功能测试、安全审查、首次恢复和压测达标 | 高危安全问题、权限/恢复失败则停止接入真实用户 |
| 邀请用户 | 14 天；指标样本满足、投诉队列时限达标；临时团队已公告 | 隐私泄漏、丢失数据、不可恢复故障关闭受影响写入 |
| 小范围公开 | 14 天；第二批选举可用且完成团队授权与独立候补池选举，新增治理验收通过，指标满足连续 7 天 | 回退邀请范围或维护模式；用户权利通道继续可用 |
| 全量公开 | 前序门槛、AI 代码与安全审核、适用测试及已知问题清单完成，项目负责人确认发布 | 触发 TECH-01/15 阈值按范围暂停，不自动扩大 |

记录 Git 提交、迁移、配置/规则/模型版本、AI 审核与测试报告、执行者和项目负责人的发布确认。先关闭故障功能，再选择兼容程序回滚；不直接逆向破坏性 SQL，不把恢复备份隐含的数据损失作为常规回滚。

单人开发不要求另设开发、测试、安全或发布审批岗位。公开招募后分批发放测试资格仍属于邀请测试，须明示资格限制、运行人员、起止日期和治理过渡，不能标为无限制注册或常态全站治理。邀请测试的最低观察期和真实用户权利不因单人开发而减少；代码审核不能替代 SA2 规定的治理选举、利益冲突回避或独立复核。

## 6. 观测与帮助

自建脱敏观测覆盖请求、任务、登录、上传、搜索、锁等待、WAL/磁盘和备份新鲜度；不记录正文、搜索原词或完整 URL 参数。功能开关按批次和 AI 模型/规则版本管理。

准备获授权示例与帮助页，覆盖已开启功能、许可选择、可见性、举报申诉、导出注销、推荐设置和治理过渡。每个验收项记录负责人、样本/报告地址、实际数值、通过/未通过/未启用状态；本文指标尚待实现和运行验证，不是已完成测试报告。

## 7. 社区治理验收与观察

治理能力按已确认的 SA2 执行，不改动一人一票、弃权计入分母及秘密选票规则。SA2 第 8 节议题规则及本轮 TECH 修订已确认；第二批上线前仍须以合成用户验证下列场景，全部通过才开放相应能力。

| 场景 | 必须满足的结果 |
|---|---|
| 联署 N 为 0、1、2、3、150、1000 和更大规模 | N=0 禁止征集，其余按 SA2 公式；一个人多个化名不叠加支持 |
| 联署撤回、排期与投票启动并发 | 投票开始前按同一快照复查数量；已开始投票不因撤回联署改变计票规则；不得重复联署 |
| 提案实质修改和错字修正 | 目标/预算/权限变化重新讨论和征集，旧支持不迁移；纯错字保持可见差异 |
| 一般提案队列与紧急补选 | 普通同时最多 3 项，顺序可追踪；法定例外有依据且不受普通名额阻塞 |
| 无人落实、逾期及旧任务重试 | 决定每 14 天更新；原期限逾期满 30 天仅创建一次复议，不修改原期限掩盖延期 |
| 被投诉团队控制案件 | 自动移交，不能自行批准或阻止独立双签；两人签名必须来自不同合资格主体 |
| 复核池不足、回避补抽、任期到期 | 不回退被投诉者终审，不新增不可逆处分；候补不足进入补选，到期/离案立刻撤销卷宗访问 |
| 定期代表确认未过半、未达法定人数和代理离任 | 进入重新选举/限期代管；30 天后授权失效；代理不自动继任或保留权限 |
| 拒绝成员申请及临时改资格标准 | 绑定申请时标准、7 天处理与申诉入口；不得按批评立场或沉默自动取消资格 |
| 跨社群总票过半但一个社群拒绝 | 不执行社群合并/治理权转移；Wiki 页面整理不擅自改变真实治理身份，个人资料另验同意 |
| 联署/回避信息的列表、通知、导出和日志 | 不暴露他人身份与个人选票；小于 10 人分组不公开交叉统计，保留期和授权撤销有效 |
| 讨论型议题升级与代表跨社群发起 | 升级生成新版本并重新讨论，旧支持不迁移；代表免联署仅限本社群直接相关议题 |
| 多方案赞成、弃权与平票补投 | 一人一份选票、按投票主体数算分母和法定人数；补投只限平票方案，每人限选一个或弃权，沿用原资格快照，仍须过半 |
| 议题广播与屏蔽 | 仅决策型发起及表决节点各一次；重复任务不多发，治理通知静音及拉黑直接提及均有效 |

先演练普通成员提案、涉代表/团队投诉和交付延期，再开启真实流程。治理观察从实际启用公告起计 60 天，第 45 天发布初步评估；记录受理时长、退回原因、复核纠正、交付延期及自愿反馈。60 天只是运行评估窗口，未有新有效决定不自动失效；规则变更必须记录版本，不中断既有案件和最低权利通道。

## 8. 社群分类与工具验收

| 场景 | 必须满足的结果 |
|---|---|
| 目录改名、移动、待分类及相关入口 | 路径无环，旧路径安全跳转；相关入口指向同一社群且不重复计数；待分类仍可搜索，分类不改治理权限或推荐权重 |
| 公告与新人指引编辑 | 仅代表或受限授权整理者可编辑，留版本和维护者；资格/规则修改不能靠公告绕过 SA2 |
| 讨论合集和作品展柜 | 原动态/回复/作品撤回、删除、隐藏或解除社群关联后立即不可见；展柜须作者主动提交，编排不改版权许可 |
| 活动日历 | 同一活动修改、取消、报名撤回后只呈现当前授权状态，不产生第二份公开参与名单 |
| 意见收集 | 一主体一份当前选择，截止前修改/撤回，公开只见汇总及自愿公开意见；关闭后不进入正式议程 |

各工具按对应批次和独立功能开关验收；未开放时页面、表单、路由及后台任务同时拒绝操作，不能用空卡片暗示已上线。

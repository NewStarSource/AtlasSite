# S03 标准单点登录与账户状态

日期 2026-10-02。用户选择只使用本地合成邮箱，真实 SMTP、域名和 HTTPS 延后至 S04。

## 已实现

- 新星账户作为 OIDC Provider，使用维护中的 `github.com/zitadel/oidc/v3`；星图作为 confidential client。
- Authorization Code + PKCE S256，固定 `client_id`、精确 redirect URI、state、nonce、签名、issuer、audience、iat/exp、auth_time、at_hash 和一次性 code。
- OIDC 授权请求绑定浏览器 Cookie；星图 state 和绑定 Cookie 只存哈希，PKCE verifier 用独立派生密钥 AES-GCM 加密，授权码只存哈希且只消费一次。
- 星图只保存账户映射、subject_id、化名、状态版本和本地会话；密码和邮箱不跨服务传递。
- 星图访问会话最长 7 天，关联账户 sid 被撤销时，下一次同步或访问复查即失效；账户服务不可用时已有有效会话保留普通访问，新登录和敏感操作暂停。
- 安全页面提供会话查看、退出、撤销全部会话；敏感操作要求最近 5 分钟内的账户重新认证。
- 账户停用会撤销会话并发出状态事件；注销后的 30 天恢复期内可重新验证密码恢复，随后须重新登录，不复活旧会话。suspended 不能由用户自行恢复。
- 身份事件使用单调序号、版本号和幂等应用；旧状态版本不会覆盖新状态。

## 初始化

两个仓库都必须使用独立的本地配置和数据库。先执行：

已有 S01/S02 配置时跳过 `init-dev`，它不会覆盖现有配置。下面的启动命令分别在各自仓库终端执行。

```powershell
Set-Location D:\NewStarProject\StarAccount
go run ./cmd/staraccount init-dev
go run ./cmd/staraccount init-oidc

Set-Location D:\NewStarProject\AtlasSite
go run ./cmd/staratlas init-dev
go run ./cmd/staratlas init-oidc
```

启动时使用本地配置：

```powershell
go run ./cmd/staraccount
go run ./cmd/staratlas
```

跨仓库初始化只复制一次随机客户端密钥；账户签名私钥留在账户服务。所有密钥和数据库位于被 Git 忽略的 `.local`，不写入聊天和提交。

## 五步人工验收

1. 打开 http://127.0.0.1:4200 ，点击“使用新星账户登录星图”。在账户端用已验证的合成账户登录/确认，返回星图后显示化名与 active 状态。
2. 打开星图“安全设置”，直接点击“撤销全部星图会话”会要求重新认证。点击“前往新星账户重新确认”，再次输入密码，返回后才能撤销。
3. 再登录星图，在新星账户 `/security` 重新确认密码后撤销当前或全部会话。返回星图刷新，应变为未登录；另一账户不能撤销本人的会话。
4. 在账户安全页确认注销测试账户，星图会话失效。前往账户 `/recover` 输入原账户密码恢复；旧会话仍无效，需要重新登录。超过 30 天或 suspended 状态不能使用恢复入口。
5. 可通过下列本地合成专用命令演练停用；UUID 从本人账户 `GET /api/v1/auth/session` 获取，禁止使用生产身份。执行后星图失效，解除停用也不会恢复旧会话。

```powershell
go run ./cmd/staraccount dev-status -account-id <合成账户UUID> -status suspended
go run ./cmd/staraccount dev-status -account-id <合成账户UUID> -status active
```

此命令只接受 synthetic 模式和 active/suspended 转换，未创建公共管理 HTTP 入口。

浏览器表单使用严格 `form-action 'self'`，所以确认后先显示“继续返回星图”链接，点击后才跨站返回；重新认证同样需要点击继续链接，避免浏览器阻断跨站表单跳转。

## 升级与恢复

升级前停止旧进程，使用 SQLite 在线备份或停止后的完整数据库副本保存 001 状态，并保留相应配置和密钥。S03 启动在事务内执行 002 迁移，单元测试验证旧账户/身份保留、部分迁移失败回滚和未知版本拒绝。无需改动生产环境。

不能将旧 S02 二进制直接用于 002 数据库。需要退回本地 S02 时停止 S03，恢复迁移前的本地合成备份和旧配置，再启动旧程序；备份之后新增的合成操作不会保留。正式恢复需撤销旧凭据并重放删除/限制清单，在 S10 验收。

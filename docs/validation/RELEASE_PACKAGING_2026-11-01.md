# 候选文档与 Linux 目标扫描

本批核对旧候选时发现首页链接指向的 LICENSE、NOTICE 不在包根目录，账户说明和部分示例链接也无法在候选目录内解析。源文档中三处示例路径多退了一层，已修正。

## 打包调整

根 README 现在是候选阅读入口，项目文档分别保留在 `projects/AtlasSite` 和 `projects/StarAccount`，两端说明、身份约定、月度记录及截图仍能相互链接。两端许可与完整依赖声明继续保留；根 LICENSE 和 NOTICE 也可直接打开。

文档只复制 Git 列出的 README、许可、docs 和 examples 文件，忽略文件不进入包。规则引用只从仓库 `reference/SAfiles` 的已纳入版本管理快照取得，原始工作区 SAfiles 不在构建时读取，也未被修改。六份快照与来源逐字节一致，版本及 SHA-256 已记录；Git 属性保留其原始混合行尾和末尾空行，索引中的文件摘要也逐一核对。

独立打包试验包含 49 份文档及材料文件，六份规则引用均可读取，包内 Markdown 本地内联链接全部可解析。新增三个临时仓库用例，验证相邻仓库链接和规则引用、忽略材料不夹带、越界目标拒绝及坏链接阻止交付，执行通过。

发布入口现在在创建输出目录前拒绝任何未提交的工作区，并在验证结束时重新核对两端提交和工作区状态。实际未提交状态下运行时退出码为 2，且没有创建候选目录。构建期间源码变化也会阻止写出最终清单。文档文件摘要进入 manifest，不能只靠手工查看 dirty 标记判断候选。

## Linux/amd64 静态扫描

使用 govulncheck v1.8.0、Go 1.27.3，在 Windows 启动扫描器并明确设置 `GOOS=linux GOARCH=amd64 CGO_ENABLED=0`。已核对扫描器的源码装载使用传入环境；这是 Linux 目标的源码分析，不描述为在 Linux 机器执行扫描器。

两端扫描均为 source/symbol 模式、退出码 0，没有 symbol 层可达发现。仍有模块或包级风险条目，未把它们删除或写成“没有任何漏洞”。原始输出摘要和风险编号见[机器可读记录](LINUX_SOURCE_SCAN_2026-11-01.json)。漏洞数据库报告的更新时间为 2026-10-27T21:16:18Z，结果只表示本次工具及数据库范围。

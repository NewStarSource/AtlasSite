# 十一月内部运行验收

本文件是待执行项与证据要求，不代表线上已经完成检查。十一月继续内部使用，未授权开启公测。本地当前数据库代码版本为星图 11、账户 6，服务器版本需独立核对。

## 版本与发布入口

两端本地均配置 GitHub 远端。配置远端不证明本地提交已推送，也不证明 CI 通过。核对远端提交、工作流运行链接和构建清单后再填写线上版本。

发布入口为 `scripts/check_release.py`，远端入口为 `.github/workflows/release.yml`。工作流必须指定两端完整提交，私有账户仓库需要具有读取权限的令牌。输出记录两端提交、未提交状态、工具链及二进制摘要。只部署已审阅的干净提交，保存构建清单；服务器不得临时拉取不确定分支重建。

发布包包含 `licenses/inventory.json` 和两端及构建所用依赖的许可文件。清单记录模块版本、适用服务、文件和摘要，不包含模块缓存的本机绝对路径。分发前还需确认接收者能够取得相应源码，不能以私有仓库存在代替交付。

## 备份与隔离恢复

新增迁移之前先使用当前线上版本取得并验证备份，保留最新独立安全记录。普通加密数据库备份与完整灾难恢复包用途不同，不把普通快照当作全部恢复依赖。

恢复依赖应覆盖两端普通备份及校验元数据、配置、加密与签名密钥、最新独立操作或安全日志及锚点、受限保存库、内容附件。具体路径从受限配置中核对，报告仅记录齐全与否。`export_recovery_bundle.sh` 会停止两端服务，打包完整恢复依赖并向指定目的地传输；它会影响现有服务，不能当作只读检查运行，实际执行前由项目负责人确认。

恢复到全新隔离目录，使用隔离端口和回调，不连接生产 OIDC，不发真实通知。普通备份恢复会清除旧会话、恢复凭据及授权，账户可能需要核验后签发短期恢复码；星图恢复清除管理与整理者授权，后续修改过的旧 Wiki 内容保持隐藏。不得复制旧权限回表或回滚最新独立安全记录。

验收至少检查内容和附件、删除与限制不复活、旧密码和恢复码不能重放、旧 OIDC 与星图会话失效、权限重新登记、合成身份的短期凭据过期及一次性消费。记录开始结束时间、耗时、备份数据时点、实际丢失区间、失败项与处理，未执行不预填 RPO/RTO 达标。

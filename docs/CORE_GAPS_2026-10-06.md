## 本地操作

从两个仓库分别启动原有 development/test 配置。已有配置可继续使用，缺少的新路径默认由 database 派生，启动时应用 Atlas schema 6 和 Account schema 5。迁移前按 [运行与恢复步骤](RUNBOOK_CORE.md) 留存停机副本。不要用旧二进制打开升级后的数据库。

从星图登录后可进行以下验收，不要求再做浏览器复现：

1. 访问 `/new` 独立发帖，打开编辑器修改，再用旧版本提交，预期收到 409；另存私人草稿，其他身份不能读取。
2. 上传自有测试图，将返回的 Markdown 放入正文。删除帖子或编辑移除图片后，旧原图和缩略图地址应返回 404。
3. 订阅社群或主题、发表回复并检查通知；在设置中隐藏关系、屏蔽另一身份，对方不能读取关系页或越过屏蔽互动。
4. 提交合成举报，由本地命令记录限制；作者能查看结论并申诉，其他用户不能读取材料；不同限制分别解除。
5. 在安全页面重新认证，导出本人数据，选择注销保留内容并通过账户服务恢复；旧会话与删除内容仍失效。

自动检查入口为 `pwsh -File scripts/check_core.ps1`。脚本依次运行两个仓库的测试、vet、漏洞扫描、构建、OIDC 失败场景和核心双服务 HTTP 流程。测试数据、邀请码、私库及备份位于临时目录，服务在结束后退出；不外发邮件，不接入真实用户。

## 已取得的验证证据

- 两个仓库全量 Go 测试与 vet 通过，涵盖旧库迁移、跨身份权限、CSRF、CAS、防重、上传、Markdown、隐藏子树、申诉、导出、注销及恢复。
- 真实双服务 HTTP 脚本通过标准 OIDC/PKCE 与 state、nonce、浏览器绑定、过期和重放失败检查；通过账户中断、重启、会话撤销、停用与注销恢复检查。
- 核心 HTTP 脚本通过真实登录后的资料回填/代理、发帖、回复、收藏、搜索、举报和选择性注销保留；两个加密备份及独立本地告警注入、去重通过。
- 原有 Goldmark 1.7.13 被扫描检出可达 XSS（GO-2026-5320），已升级到 1.7.17。修复后两个服务均未检出应用可达漏洞；扫描仍报告依赖树中未被当前应用调用的已知问题。
- 小型合成库隔离恢复样本耗时 34 ms；包括清单重放、会话清除和完整性检查。这不能代表真实部署或磁盘灾难恢复耗时。
- 100 个合成账户、2,000 条动态、100 个同时发起的 handler 客户端、200 次匿名读请求的短样本，补充索引后耗时约 399 ms，P50 106.90 ms、P95 295.70 ms、P99 383.37 ms。该样本没有网络传输，也没有覆盖正式容量、登录压测或连续 30 分钟负载。
- 当前未运行 race 检查；本机没有配置所需 C 工具链。已运行受控并发读样本及事务、版本、幂等和任务状态测试。
